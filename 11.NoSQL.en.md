# NoSQL Databases Notes

Goal: understand why NoSQL exists, its main types, the BASE tradeoff, and the core ideas of Document/Graph/MapReduce.

---

## 1. Why NoSQL
Relational databases are not always the best fit:
- massive scale and high concurrency
- rapidly changing, heterogeneous data
- deep relationships where joins are expensive

Conclusion: use the right model for the right problem.

---

## 2. Four Main NoSQL Types
1. **Key–Value** (e.g., Dynamo)
2. **Column-oriented** (e.g., Bigtable / HBase)
3. **Document-oriented** (e.g., MongoDB)
4. **Graph** (e.g., Neo4j)

---

## 3. ACID vs BASE
NoSQL commonly uses **BASE**:
- **Basically Available**
- **Soft State**
- **Eventual Consistency**

Contrast:
- **ACID**: strong consistency, good for finance/transactions
- **BASE**: scalability and availability with temporary inconsistency

---

## 4. Document Store (MongoDB)
Core ideas:
- documents (JSON/BSON) are the storage unit
- documents in the same collection can have different shapes
- **schema-on-read**

![Document store example](relational_db/images/document%20oriented%20data%20stores.png)

RDBMS mapping:
| RDBMS | MongoDB |
| --- | --- |
| table | collection |
| row | document |
| join | embed / reference |
| primary key | _id |

### Embedding vs Referencing
- **Embedding**: 1–1 / 1–many, fast reads, higher redundancy
- **Referencing**: many–many, flexible, requires extra queries

## 5. Graph DB (Neo4j)
Model elements:
- **Node**: entity
- **Relationship**: directed, typed
- **Property**: attributes
- **Label**: grouping

Advantage: deep relationship traversal is much faster than multi-table joins.

---

## 6. MapReduce (Programming Model)
A parallel model for large-scale data processing:
- **Map**: emit `(key, value)`
- **Shuffle**: group by key
- **Reduce**: aggregate values by key

Classic example: Word Count.

---

## 7. When to Use SQL vs NoSQL
| Scenario | Better Fit |
| --- | --- |
| Strong transactional consistency | SQL |
| High-throughput reads/writes | NoSQL |
| Semi-structured data | Document |
| Deep relationship analysis | Graph |
| Simple key-value access | Key–Value |

---

## One-Sentence Summary
NoSQL trades strong ACID guarantees for scalability and performance, offering document, graph, column-family, and key–value models for large-scale, flexible, or highly connected data.

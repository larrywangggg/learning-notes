# NoSQL 数据库整理

目标：理解为什么需要 NoSQL、主要类型、BASE 取舍，以及 Document/Graph/MapReduce 的核心思想。

---

## 1. 为什么需要 NoSQL
关系型数据库并非万能：
- 数据规模巨大、并发极高
- 数据结构变化快、异构
- 关系层级很深（多表 join 性能差）

结论：**用合适的模型解决合适的问题**。

---

## 2. NoSQL 四大类型（必背）
1. **Key–Value**（如 Dynamo）
2. **Column-oriented**（如 Bigtable / HBase）
3. **Document-oriented**（如 MongoDB）
4. **Graph**（如 Neo4j）

---

## 3. ACID vs BASE
NoSQL 常用 **BASE**：
- **Basically Available**：整体可用
- **Soft State**：状态可在无输入时变化
- **Eventual Consistency**：最终一致

对比：
- **ACID**：强一致，适合金融/交易
- **BASE**：可扩展、可容忍短暂不一致

---

## 4. Document Store（MongoDB）
核心思想：
- 文档（JSON/BSON）是存储单位
- 同一 collection 内文档结构可不同
- **Schema-on-read**（读时解释）

![Document Store 示例](relational_db/images/document%20oriented%20data%20stores.png)

RDBMS 对照：
| RDBMS | MongoDB |
| --- | --- |
| table | collection |
| row | document |
| join | embed / reference |
| primary key | _id |

### Embedding vs Referencing
- **Embedding**：1-1 / 1-many，读取快，冗余高
- **Referencing**：many-many，灵活，但需要多次查询

## 5. Graph DB（Neo4j）
模型要素：
- **Node**：实体
- **Relationship**：有方向、有类型
- **Property**：属性
- **Label**：分类

优势：深层关系查询（friends-of-friends）比多表 join 快得多。

---

## 6. MapReduce（编程模型）
面向大规模数据的并行计算模型：
- **Map**：输出 `(key, value)`
- **Shuffle**：按 key 分组
- **Reduce**：聚合同一 key 的 values

经典例子：Word Count。

---

## 7. 什么时候用 SQL / NoSQL
| 场景 | 更合适 |
| --- | --- |
| 强一致事务 | SQL |
| 高并发读写 | NoSQL |
| 异构/半结构化数据 | Document |
| 深层关系分析 | Graph |
| 简单键值访问 | Key–Value |

---

## 一句话总结
NoSQL 用 BASE 换取扩展性与性能，提供文档、图、列族和键值等模型，适合大规模、灵活或高度关联的数据场景。

# 关系代数（Relational Algebra）整理

目标：理解 SQL 查询的逻辑过程，掌握常用运算与 Join 的本质。
---
## 学习意义
掌握关系代数能让你把 SQL 查询还原成清晰的逻辑步骤，从而判断查询是否正确、为什么等价、以及优化能否安全进行。它也是理解查询优化器行为、证明等价变换与设计高效查询的基础能力。 
---

## 1. 基本前提（必记）
- **输入/输出都是关系（relation）**
- **集合语义**：无重复元组
- **无序**：行、列都没有顺序

影响：
- 投影会自动去重
- 不能依赖“第几行”“顺序”

---

## 2. 一元运算（基础工具）
- **选择 σ**：筛行（对应 WHERE）
- **投影 π**：选列（对应 SELECT），**自动去重**
- **重命名 ρ**：改名（用于 self-join、division 等）

---

## 3. 二元运算（重点）

### 3.1 集合运算（对整行做集合操作）
- **并集 ∪**：要求同构（属性数/域兼容）
- **交集 ∩**
- **差集 −**

SQL 对应：`UNION`、`INTERSECT`、`EXCEPT`

---

### 3.2 笛卡尔积 ×（Join 的数学基础）
定义：  
R × S = R 的每个元组与 S 的每个元组配对。

特点：
- 若 R 有 m 行，S 有 n 行，结果为 **m × n 行**
- 单独使用意义不大，通常作为 Join 的中间步骤

核心等式：  
**Join = Cartesian Product + Selection**

---

### 3.3 Join（最核心）

#### 3.3.1 θ-Join（最一般）
定义：
```
R ⋈θ S = σθ (R × S)
```
θ 可为任意条件（=, ≠, <, >, ≤, ≥ 或组合条件）。

#### 3.3.2 Equi-Join（常用）
- θ-Join 的特例，条件只包含等号
- **两边等值列都会保留**（不自动消重）

SQL 对应：
```sql
FROM R JOIN S ON R.a = S.b
```

#### 3.3.3 Natural Join（简洁但危险）
- 自动找到**同名属性**
- 先 equi-join，再**合并同名列**
- 属性名改变会导致语义变化

SQL 对应：
```sql
NATURAL JOIN
```

---

### 3.4 Join 结果结构（考点）
| Join 类型 | 同名属性 | 是否去重 |
| --- | --- | --- |
| θ-join | 保留 | 不去重 |
| equi-join | 保留 | 不去重 |
| natural join | 合并 | 去重 |

---

## 4. 与查询优化的关系
关系代数解释了优化的合法性：
- join 顺序可变（结合律/交换律）
- selection 可下推
- projection 可下推
- Cartesian product 越晚越好

这些原则是后续 **Query Optimisation** 的基础。

---

## 一句话总结
关系代数用集合运算形式化查询过程，核心是 **Join = × + σ**，并为 SQL 语义理解与查询优化提供理论基础。

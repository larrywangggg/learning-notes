# 事务与并发控制（Transactions & Concurrency）整理

目标：理解事务的 ACID 特性、日志恢复、锁与并发异常，以及隔离级别的取舍。

---

## 1. 事务（Transaction）
定义：**一组数据库操作作为一个逻辑单元执行**，要么全成功，要么全回滚。

典型例子（转账）：
```sql
BEGIN;
UPDATE account SET balance = balance - 500 WHERE name = 'Steve';
UPDATE account SET balance = balance + 500 WHERE name = 'Bob';
COMMIT;
```

---

## 2. ACID（核心概念）
- **Atomicity（原子性）**：要么全做，要么全不做
- **Consistency（一致性）**：事务前后满足约束  
  *应用开发者负责业务一致性，DBMS 保证 A/I/D*
- **Isolation（隔离性）**：并发事务互不干扰
- **Durability（持久性）**：提交后结果不会丢失

## 3. 日志与恢复（保证 A + D）
**WAL（Write-Ahead Logging）规则：**
1. **先写日志，再写数据**
2. **commit 前日志必须落盘**

恢复时：
- **UNDO** 未提交事务
- **REDO** 已提交但未写入磁盘的事务

![WAL 示意](images/WAL.png)

---

## 4. 并发控制：锁与 2PL
### 锁的类型
- **Shared lock（读锁）**
- **Exclusive lock（写锁）**

### Two-Phase Locking（2PL）
- **Growing phase**：只加锁，不释放
- **Shrinking phase**：只释放，不加锁

优点：保证可串行化  
缺点：可能死锁、降低并发

---

## 5. 可串行化（Serializability）
定义：并发执行结果等价于某种串行顺序。

判断思路：
- 能等价于 `T1 -> T2` 或 `T2 -> T1` 即可
- 否则不可串行化

---

## 6. 并发异常（考试高频）
- **Lost Update**：写写冲突，后写覆盖前写
- **Dirty Read**：读到未提交数据
- **Unrepeatable Read**：同一行两次读结果不同
- **Phantom Read**：同一查询返回的行集合变化

---

## 7. 隔离级别（SQL）
常见四级：

| Isolation Level | Dirty Read | Unrepeatable Read | Phantom Read |
| --- | --- | --- | --- |
| READ UNCOMMITTED | ✔ | ✔ | ✔ |
| READ COMMITTED | ✘ | ✔ | ✔ |
| REPEATABLE READ | ✘ | ✘ | ✔ |
| SERIALIZABLE | ✘ | ✘ | ✘ |

取舍原则：隔离越高越安全，但性能越低。

---

## 一句话总结
事务保证 ACID，日志与恢复保证 A/D，锁与 2PL保证隔离性；隔离级别在安全与性能之间取舍。

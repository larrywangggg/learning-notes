# 数据库安全（Database Security）整理

目标：理解安全目标（CIA）、访问控制模型（DAC/MAC/RBAC）与常见攻击（SQL 注入）及其防御。

---

## 1. 安全目标（CIA）
- **Confidentiality（机密性）**：只有授权用户可读
- **Integrity（完整性）**：只有授权用户可改，且数据正确
- **Availability（可用性）**：授权用户需要时可访问

---

## 2. 访问控制模型
### 2.1 DAC（Discretionary Access Control）
- 资源有 **owner**
- owner 决定谁能访问、能做什么、是否能再授权
- SQL 机制：`GRANT` / `REVOKE`

**GRANT OPTION / REVOKE 要点：**
- 有 `WITH GRANT OPTION` 才能再授权
- `REVOKE ... RESTRICT`：阻止撤销（若仍依赖）
- `REVOKE ... CASCADE`：级联撤销
- 多来源授权时，只要保留一条来源，权限仍有效

**示例：**
```sql
-- Alice 将 SELECT 授权给 Bob，并允许 Bob 继续授权
GRANT SELECT ON Student TO Bob WITH GRANT OPTION;

-- Bob 再授权给 Carol（只有有 GRANT OPTION 才能这样做）
GRANT SELECT ON Student TO Carol;

-- 撤销 Alice -> Bob 的授权（若 Bob 仍向下授权，RESTRICT 会拒绝）
REVOKE SELECT ON Student FROM Bob RESTRICT;

-- 级联撤销：Bob 和他再授权出去的权限都会被回收
REVOKE SELECT ON Student FROM Bob CASCADE;
```

**多来源授权示例：**
```sql
-- Alice 和 David 都给 Bob 授权
GRANT SELECT ON Student TO Bob WITH GRANT OPTION;
GRANT SELECT ON Student TO Bob; -- 来自 David

-- 即使撤销 Alice 的授权，Bob 仍保留来自 David 的那条权限
REVOKE SELECT ON Student FROM Bob CASCADE;
```

**RESTRICT vs CASCADE 直觉：**
- `RESTRICT`：如果撤销会影响其他用户的权限，系统拒绝撤销
- `CASCADE`：允许撤销，并把依赖它的授权一并回收

---

### 2.2 MAC（Mandatory Access Control）
- 系统集中控制，用户不能自行更改权限
- 用户有 **clearance**，对象有 **classification**

**Bell–LaPadula 规则（必背）：**
- **Read down**：clearance(subject) ≥ class(object)
- **Write up**：clearance(subject) ≤ class(object)

目的：防止高密级信息向低密级泄露。

---

### 2.3 RBAC（Role-Based Access Control）
- 权限赋给角色，用户通过角色获得权限
- 便于大规模组织管理

---

## 3. DAC vs MAC（常考对比）
| 维度 | DAC | MAC |
| --- | --- | --- |
| 灵活性 | 高 | 低 |
| 权限传播 | 用户可再授权 | 系统强制 |
| 防止信息泄露 | 较弱 | 强 |
| 典型攻击 | Trojan Horse | 较难 |

---

## 4. SQL Injection（现实高频）
根因：**把用户输入拼进 SQL**，控制与数据不分离。

常见攻击：
- `OR 1=1` 绕过认证
- `UNION SELECT` 读其他表
- `; DROP TABLE` 破坏数据

## 5. 防御 SQL Injection（标准答案）
**最可靠方案：参数化查询（Parameterized Queries）**

核心原则：**Separation of control and data**  
SQL 结构固定，输入只作为参数绑定。

示例：
```sql
SELECT * FROM users WHERE username = ?
```

不推荐：
- 黑名单（易绕过）
- 仅靠 escaping
- 仅靠 firewall/IDS

---

## 一句话总结
数据库安全通过 CIA 目标与访问控制机制保证数据安全，同时必须用参数化查询抵御 SQL 注入等现实攻击。

# Ed25519 SSH Key Usage Guide

## 1. What Is Ed25519?

Ed25519 is a modern, high-security, and efficient elliptic-curve digital signature algorithm (EdDSA).
It is widely recommended for SSH key authentication as a replacement for traditional RSA.

Compared with RSA, Ed25519 provides:

- Higher security with shorter key sizes
- Faster key generation and signature verification
- Shorter, easier-to-manage key length

### Key Length Comparison

- **Ed25519**: about 68 characters
- **RSA 3072-bit**: about 544 characters

Therefore, Ed25519 has become the default and recommended choice in modern systems.

---

## 2. Why Use Ed25519?

### Security
- A smaller key can still provide a high security level
- The design avoids some implementation risks in traditional algorithms

### Performance
- Faster generation and verification than RSA and ECDSA

### Convenience
- Smaller keys are easier to copy, paste, and manage

### Compatibility
- Native support in OpenSSH 6.5 and later
- Standard configuration on modern Linux / macOS / Windows systems

---

## 3. Generate an Ed25519 SSH Key

Run the following command in the terminal (Linux / macOS / Windows PowerShell all work):

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

### Generation Details

1. **Save path**
   - Press Enter to use the default path:
     ```text
     ~/.ssh/id_ed25519
     ```
   - This is the OpenSSH standard location. Keep the default so tools can auto-detect it.

2. **Passphrase**
   - Strongly recommended for private keys
   - Adds another layer of protection if the private key is copied or leaked
   - On macOS, Keychain can unlock automatically, so daily use is nearly frictionless

3. **Result**
   - Two files are created:
     - Private key: `~/.ssh/id_ed25519`
     - Public key: `~/.ssh/id_ed25519.pub`

---

## 4. How to Use the SSH Key

### 4.1 Start ssh-agent

Before using the SSH key, make sure ssh-agent is running:

```bash
eval "$(ssh-agent -s)"
```

**After that**, there will be no more semantic or structural jumps.

ssh-agent is a background process that securely manages loaded private keys. Its main roles are:

- Securely keep unlocked private keys in memory
- Avoid retyping the passphrase every time you use SSH
- Provide a unified key access interface for Git, SSH, and automation tools

ssh-agent does not generate keys. It only **hosts and forwards key operations**.

---

### 4.2 Add the private key to ssh-agent

With ssh-agent running, load the private key:

```bash
ssh-add ~/.ssh/id_ed25519
```

If the private key has a passphrase, you will be prompted once.

#### macOS recommended method

On macOS, use:

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

This securely stores the passphrase in Keychain, which enables:

- No passphrase prompt after restarting the terminal
- A near "passwordless" SSH experience
- Private keys remain encrypted

### 4.3 Verify the private key is loaded

Check the keys currently loaded in ssh-agent:

```bash
ssh-add -l
```

If the output includes something like:

```text
256 SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx id_ed25519 (ED25519)
```

Then:

- The private key is loaded
- ssh-agent is working properly
- The current session can use SSH authentication

### 4.4 Add the public key to a server or Git platform

View and copy the public key:

```bash
cat ~/.ssh/id_ed25519.pub
```

Add the full line output to one of the following:

- Remote server `~/.ssh/authorized_keys`
- GitHub / GitLab SSH Keys settings page

Security notes:

- Only upload or paste the `.pub` file content (public key)
- Never upload, share, or commit the private key to any repository
- Public key exposure is safe; private key exposure is catastrophic

## 5. Optional: Hardware security keys (FIDO2)

For higher security (for example, production servers or enterprise environments), you can use FIDO2-based hardware security keys:

```bash
ssh-keygen -t ed25519-sk -C "your_email@example.com"
```

### Key points

- Requires a physical security device (such as YubiKey)
- The private key stays on the hardware and cannot be exported
- Each use requires physical confirmation (touch the device)

If the hardware does not support Ed25519, use:

```bash
ssh-keygen -t ecdsa-sk
```

## 6. Practical Summary

- ssh-agent manages private key usage permissions, not public keys
- Private keys stay on the local machine or hardware devices
- Public keys declare your identity to external systems
- Ed25519 is the current best practice for SSH
- One SSH key pair can be used for GitHub, GitLab, servers, and CI systems

## 7. One-line version to remember

- ssh-agent decides "whether to use the key"
- The private key proves "who you are"
- The public key is just "registration info"

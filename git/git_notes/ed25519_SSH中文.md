# Ed25519 SSH Key 使用指南

## 1. 什么是 Ed25519？

Ed25519 是一种现代、高安全性且高效率的椭圆曲线数字签名算法（EdDSA），  
目前被广泛推荐用于 SSH 密钥认证，作为对传统 RSA 的替代方案。

与 RSA 相比，Ed25519 具有：

- 更高的安全性（在更小密钥长度下）
- 更快的密钥生成与签名验证速度
- 更短、更易管理的密钥长度

### 密钥长度对比

- **Ed25519**：约 68 个字符
- **RSA 3072-bit**：约 544 个字符

因此，Ed25519 已成为现代系统中的默认与推荐选择。

---

## 2. 为什么使用 Ed25519？

### Security（安全性）
- 使用更小的密钥即可提供高等级安全性
- 设计上避免了部分传统算法的实现风险

### Performance（性能）
- 相比 RSA 和 ECDSA，生成和验证速度更快

### Convenience（便利性）
- 密钥体积小，更容易复制、粘贴和管理

### Compatibility（兼容性）
- OpenSSH 6.5 及以上版本原生支持
- 已成为现代 Linux / macOS / Windows 系统的标准配置

---

## 3. 生成 Ed25519 SSH Key

在终端中运行以下命令（Linux / macOS / Windows PowerShell 均适用）：

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

### 生成过程说明

1. **保存路径**
   - 按回车使用默认路径：
     ```text
     ~/.ssh/id_ed25519
     ```
   - 这是 OpenSSH 的标准位置，推荐保持默认，便于工具自动识别。

2. **Passphrase**
   - 强烈建议为私钥设置一个 passphrase
   - 作用是在私钥文件被拷贝或泄露时，提供额外一层保护
   - 在 macOS 上，可配合 Keychain 实现自动解锁，日常使用几乎无感

3. **生成结果**
   - 成功后将生成以下两个文件：
     - 私钥（private key）：`~/.ssh/id_ed25519`
     - 公钥（public key）：`~/.ssh/id_ed25519.pub`

---

## 4. 如何使用 SSH Key

### 4.1 启动 ssh-agent

在使用 SSH key 之前，需确保 ssh-agent 正在运行：

```bash
eval "$(ssh-agent -s)"
```


**之后**，不会再出现语义或结构跳跃。

ssh-agent 是一个后台进程，用于在系统层面安全地管理已加载的私钥。它的主要作用包括：

- 在内存中安全地保存已解锁的私钥
- 避免每次使用 SSH 时重复输入 passphrase
- 为 Git、SSH、自动化工具提供统一的密钥访问接口

ssh-agent 本身并不生成密钥，只负责**托管和转发密钥操作请求**。

---

### 4.2 将私钥加入 ssh-agent

在 ssh-agent 运行的前提下，需要将刚生成的私钥加载进去：

```bash
ssh-add ~/.ssh/id_ed25519
```
如果私钥设置了 passphrase，此时会提示输入一次。

#### macOS 推荐方式

在 macOS 系统上，建议使用以下命令：

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```


该方式会将 passphrase 安全地存储在系统 Keychain 中，从而实现：

- 重启终端后无需重新输入 passphrase

- SSH 使用体验接近“无感认证”

- 同时保持私钥的加密保护


### 4.3 验证私钥是否成功加载

可以通过以下命令查看当前 ssh-agent 中已加载的密钥：

```bash
ssh-add -l
```

如果输出中包含类似内容：

```text
256 SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx id_ed25519 (ED25519)
```

则说明：

- 私钥已成功加载
- ssh-agent 工作正常
- 当前会话可以使用 SSH 进行认证

### 4.4 将公钥添加到服务器或 Git 平台

查看并复制公钥内容：

```bash
cat ~/.ssh/id_ed25519.pub
```

将输出的完整一行内容添加到以下位置之一：

- 远程服务器的 `~/.ssh/authorized_keys`
- GitHub / GitLab 的 SSH Keys 设置页面

⚠️ 安全注意事项：

- 只能上传或粘贴 `.pub` 文件内容（公钥）
- 私钥文件绝不能上传、分享或提交到任何仓库
- 公钥泄露是安全的，私钥泄露是灾难性的

## 5. 可选方案：硬件安全密钥（FIDO2）

在需要更高安全级别（例如生产服务器或企业环境）时，可以使用基于 FIDO2 的硬件安全密钥：

```bash
ssh-keygen -t ed25519-sk -C "your_email@example.com"
```

### 特点说明

- 需要物理安全设备（如 YubiKey）
- 私钥始终保存在硬件中，无法被导出
- 每次使用都需要物理确认（触碰设备）

如果硬件不支持 Ed25519，可改用：

```bash
ssh-keygen -t ecdsa-sk
```

## 6. 实践总结

- ssh-agent 负责管理私钥的使用权限，而非存储公钥
- 私钥只存在于本地或硬件设备中
- 公钥用于向外部系统声明身份
- Ed25519 是当前 SSH 的最佳实践算法
- 同一套 SSH key 可用于 GitHub、GitLab、服务器与 CI 系统

## 7. 一句话记忆版

- ssh-agent 管理“用不用这把钥匙”
- 私钥证明“你是谁”
- 公钥只是“登记信息”
